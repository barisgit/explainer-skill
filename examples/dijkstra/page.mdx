# Dijkstra's algorithm with a *negative edge*

In a graph of {EDGES.length} one-way edges, one of them negative, Dijkstra gives the distance from S to {TARGET} as {DIJKSTRA.dist[TARGET]} where the shortest path is {BELLMAN.dist[TARGET]}.

```ts ref:init="dist[source] = 0" ref:pick="takeNearest(queue)" ref:skip="if (settled.has(v)) continue;" ref:relax="dist[u] + w < dist[v]"
dist[source] = 0;
while (queue.length) {
  const u = takeNearest(queue);
  settled.add(u);
  for (const [v, w] of edges[u]) {
    if (settled.has(v)) continue;
    if (dist[u] + w < dist[v]) dist[v] = dist[u] + w;
  }
}
```

Settling a node means declaring its distance final. That holds only if every later path is at least as long, which needs every edge to be zero or more.

## Bellman–Ford

Bellman–Ford checks {BELLMAN.checks} edges where Dijkstra checks {DIJKSTRA.checks}. It never settles: it relaxes every edge V − 1 times over, so any distance can still drop. That is O(V·E) against Dijkstra's O((V + E) log V), and it reports a negative cycle, where no shortest path exists.

## Does adding {SHIFT} to every weight fix it?

<Question name="shift" options={{ yes: "Yes: no negative edges, so Dijkstra is right", no: "No: it picks another path" }} answer="no">

The weights become {EDGES.map(([, , w]) => w + SHIFT).join(", ")} and Dijkstra returns {SHIFTED_PATH.join(" → ")}, which costs {SHIFTED_COST} in the original graph, not {BELLMAN.dist[TARGET]}. A path of two edges pays the {SHIFT} twice, so the best path changes.
